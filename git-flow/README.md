# **Git Flow**

Описание рабочего процесса (workflow) на основе Git: как организована работа с ветками, коммитами и релизами, чтобы командная разработка была предсказуемой.  

* **Git Flow** — это модель ветвления для Git, которая предлагает чёткую структуру для организации командной разработки. Её предложил Винсент Дриссен в 2010 году. Суть подхода в том, чтобы разделить жизненный цикл проекта на этапы с помощью разных типов веток, что помогает контролировать стабильность кода, упрощать релизы и вести параллельную работу.

## Зачем эта папка

Git даёт свободу — а без договорённостей эта свобода превращается в хаос: кто-то коммитит прямо в main, названия веток отличаются, история непонятна.  

**GitFlow** — это набор правил, которые делают процесс единообразным: понятно, где ведётся разработка, как выходят релизы и куда летят срочные исправления.

## Что здесь есть

- **Схема веток** — назначение main, develop, feature, release и hotfix,
  и как они взаимодействуют.
- **Правила именования** — как называть ветки и писать коммиты (conventional commits).
- **Жизненный цикл фичи** — от создания ветки до вливания через Pull Request.
- **Работа с релизами и хотфиксами** — порядок действий при выпуске версии
  и срочном исправлении бага в продакшене.
- **Примеры сценариев** — пошаговые последовательности команд для типовых задач.

## Как пользоваться

Используйте как справочник процесса: перед началом работы сверьтесь с правилами именования, при спорных ситуациях — с описанием жизненного цикла веток. Материалы рассчитаны на новичков и служат единым источником истины для команды.
